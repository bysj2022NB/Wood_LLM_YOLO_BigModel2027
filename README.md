# 计算机毕业设计基于YOLO目标检测+多模态AI大模型分析的木材缺陷智能检测分析预警系统(源码+LW+PPT+讲解)
# 基于「YOLO 目标检测 + 多模态 AI 分析」的木材缺陷智能检测分析预警系统 

## 项目概述

WoodGuard 是一套面向 Windows 10/11 x64 的木材缺陷检测分析预警桌面系统。系统使用 Electron 构建本地桌面 GUI，以 Vue 3 提供交互界面，由 Electron 主进程启动并管理仅监听 `127.0.0.1:5020` 的 Flask 服务；YOLO 负责木材缺陷定位与分类，ByteTrack 负责实时目标跟踪，多模态大模型按用户操作对检测结果进行二次复核。数据、模型权重、训练产物、上传文件、检测结果、报告和日志均存放在项目根目录 `runtime`，形成从数据准备、模型训练和评估到图片、视频、实时检测及预警处置的本地业务闭环。

系统当前识别四类木材缺陷：裂纹（Crack）、死节（Dead Knot）、活节（Live Knot）和髓心（Marrow）。YOLO 检测结论与大模型复核结论分开展示；图片、视频关键帧和实时预警只有在用户点击“大模型复核”后才调用 AI 服务，未配置模型、请求超时、触发限流或返回异常时保留原始 YOLO 结果，并明确显示降级原因，不生成模拟检测结果。

### 核心创新点

1. **桌面化一体运行**：Electron 集成 Vue 3 客户端和本机 Flask 服务，保留可拖动窗口工具栏，并负责后端健康检查、版本检查、端口冲突提示及退出清理。
2. **多场景缺陷检测**：支持单张图片、视频文件和摄像头实时检测，检测结果包含中文类别、置信度、位置、标注图、裁剪图或关键帧等信息。
3. **完整模型生命周期**：支持从 `runtime/models/base-weights` 选择 YOLO 基础权重，配置 CPU/GPU、训练轮次、批大小、图像尺寸、优化器、学习率等参数，并完成训练、续训、取消、权重导入、发布、取消发布和删除。
4. **实时训练监控**：通过 Socket.IO 推送批次与轮次进度，展示预计剩余时间、已用时间、Precision、Recall、mAP50、训练损失和实时日志；提前停止或正常完成时同步归一化最终进度和状态。
5. **可控多模型复核**：默认 GLM 视觉模型从后端 `.env` 读取，动态文本/视觉模型及访问顺序保存在 `runtime/config/ai-models.json`；系统按能力和自定义顺序调用，失败后自动切换下一服务。
6. **智能实时预警**：结合 YOLO、ByteTrack、识别间隔、置信度、IoU 和会话级去重生成预警，支持五级严重程度、导航红点提醒、详情查看、大模型复核、单条处置、全选、批量处置与批量删除。
7. **可复现模型评估**：支持上传单张测试图片及同名 YOLO 标签 `.txt`，计算 Precision、Recall、mAP50、mAP50-95，并展示真实 Precision–Recall 曲线及本次评估的类别指标和运行信息；创建新任务时清理页面中的旧结果。
8. **安全账户体系**：支持账号密码、手机短信验证码登录及短信验证后重置密码，使用 JWT Bearer 鉴权、角色权限控制和 Argon2id 密码哈希，并兼容旧 MD5 密码首次登录迁移。
9. **本地数据治理**：SQLite 开启外键和 WAL，文件通过 bucket/object_key 映射，运行目录具备首次创建、可写检查、磁盘状态、日志轮转、临时文件清理及路径穿越防护。

### 应用场景

- **木材加工产线**：辅助原木、板材进料、加工和分拣环节发现表面缺陷。
- **质量检验与分级**：按缺陷类别、数量、置信度和风险等级提供抽检、复核与处置依据。
- **仓储与贸易**：保存来料检验、出库抽检、视频任务和预警记录，支持详情追溯。
- **模型研发与教学**：覆盖数据集校验、数据划分、模型训练、实时监控、指标评估和结果分析流程。
- **本地敏感场景**：业务数据默认留存在单机 `runtime`，Flask 端口不向局域网或公网开放。

## 技术架构

### 整体架构设计

系统采用 Electron 桌面客户端、本机业务服务、算法服务和本地存储相互分层的架构：

```text
┌──────────────────────────────────────────────────────────────┐
│ Electron 桌面客户端                                          │
│ ┌──────────────┐  白名单 IPC  ┌───────────────────────────┐ │
│ │ Electron 主进程│◄───────────►│ 安全 preload 层            │ │
│ │ 窗口/子进程管理│              │ 文件选择/目录/窗口/令牌能力 │ │
│ └───────┬──────┘              └─────────────┬─────────────┘ │
│         │                         Vue 3 渲染层 │               │
└─────────┼─────────────────────────────────────┼───────────────┘
          │ 启动、健康检查、退出清理             │ REST / Socket.IO
          ▼                                     ▼
┌──────────────────────────────────────────────────────────────┐
│ Flask 本机服务（127.0.0.1:5020，统一前缀 /api/v1）           │
│ 认证权限 │ 业务 API │ 异步任务 │ 统一响应/异常 │ 文件访问控制 │
└───────────────────────┬───────────────────────┬──────────────┘
                        │                       │
          ┌─────────────▼────────────┐  ┌──────▼────────────────┐
          │ 算法与外部 AI 服务层      │  │ 本地数据与文件存储层   │
          │ YOLO / ByteTrack / OpenCV│  │ SQLite + runtime       │
          │ GLM / 动态文本与视觉模型  │  │ bucket / object_key    │
          └──────────────────────────┘  └───────────────────────┘
```

Electron 启动时先检查 `5020` 端口。如果发现兼容的 WoodGuard 服务则复用；若端口被旧版后端或其他程序占用则给出明确提示；若端口空闲则使用 `项目代码/server/.venv` 中的 Python 3.13 启动 Flask，等待健康检查通过后再显示主窗口。应用退出时仅清理由当前 Electron 进程创建的后端子进程。

渲染层通过 `/api/v1` REST API 进行查询和提交，统一响应格式为 `{code, message, data}`；视频处理、模型训练、模型评估和实时检测状态通过 Socket.IO 推送。文件不以任意绝对路径暴露，而是使用受控 bucket 与 object_key 获取，后端会拦截绝对路径、盘符、`..`、符号链接和越界访问。

### 技术栈详解

#### 前端技术栈（desktop-client）

- **桌面运行容器**：Electron 43.3.0，负责无边框/自定义工具栏窗口、本机服务生命周期、窗口状态和安全存储。
- **核心框架**：Vue 3.5.41，使用 Composition API 与 TypeScript 6.0.3。
- **组件与图标**：Element Plus 2.14.4、`@element-plus/icons-vue` 2.3.2，并结合项目自定义森林/木材主题样式。
- **状态管理**：Pinia 4.0.2，维护身份、全局状态、异步任务、预警通知和系统设置。
- **路由管理**：Vue Router 5.2.0，采用 Hash 路由并按管理员/普通用户角色实施页面守卫。
- **网络通信**：Axios 1.19.0 调用 REST API，Socket.IO Client 4.8.3 接收训练、视频、评估和实时检测事件。
- **图表可视化**：ECharts 6.1.0，用于指标、趋势和 Precision–Recall 曲线等展示。
- **构建与质量**：Vite 8.2.1、Vue TSC、ESLint、Vitest 和 Playwright。
- **安全配置**：`nodeIntegration=false`、`contextIsolation=true`、`sandbox=true`、严格 CSP、导航限制和外链白名单；renderer 只能调用 preload 暴露的白名单 IPC。

#### 后端+算法端技术栈（server）

- **运行环境**：Python 3.13.x，项目当前按 Python 3.13.1 建立虚拟环境。
- **Web 与实时通信**：Flask 3.1.3、Flask-SocketIO 5.6.1 和 simple-websocket。
- **数据库与迁移**：SQLite 3、SQLAlchemy 2.0.51、Flask-SQLAlchemy 3.1.1、Flask-Migrate/Alembic。
- **认证与安全**：PyJWT 2.8.0、Argon2id、访问/刷新令牌、管理员权限中间件、上传校验和对象键路径防护。
- **图像与视频处理**：OpenCV 5.0.0、NumPy 2.5.2、Pillow，支持 CLAHE、视频采样、关键帧、缩略图、标注图和裁剪图生成。
- **目标检测与跟踪**：Ultralytics 8.4.117，支持 YOLOv8、YOLO11、YOLO12、YOLO26 权重以及 ByteTrack 实时跟踪；默认训练基线为 `yolo26n`。
- **多模态与文本 AI**：默认 GLM 视觉服务及 OpenAI 兼容动态模型，使用 HTTPX 请求、超时重试、限流退避、结构化校验、结果缓存和顺序兜底。
- **报告生成**：python-docx 1.2.0 生成图片检测 Word 报告。
- **测试与检查**：Pytest、Ruff、Mypy；依赖分别通过运行、开发和 CUDA 锁文件管理。

## 核心功能模块

1. **用户认证与账户安全**：支持账号密码注册/登录、手机短信验证码登录、短信验证后重置密码、访问令牌刷新、退出登录和修改密码；管理员可管理用户角色及启用/禁用状态。
2. **工作台**：汇总用户、数据集、模型、图片检测、视频任务、实时预警及系统运行状态，为管理员和普通用户展示符合权限的数据概览。
3. **数据集管理**：支持导入 ZIP 格式 YOLO 数据集，执行安全解压、目录结构、图片/标签对应关系、类别编号、标注格式和数据统计校验；支持重新校验、删除和内置数据准备，原始数据保持只读。
4. **模型管理与训练**：创建模型时可选择本地基础权重、训练数据集、CPU/GPU、epochs、batch、imgsz、patience、workers、seed、优化器、学习率、AMP、cache 等参数。训练在独立 Python 子进程中运行，页面实时显示批次/轮次进度、预计剩余时间、Precision、Recall、mAP50、损失和日志，并支持取消、续训、导入权重、发布、取消发布、设为默认及删除。系统启动不会自动新增模型，也不会自动下载基础权重。
5. **图片检测与图片记录**：上传后立即显示缩略图，用户可选择模型、置信度、IoU 和 CLAHE 等参数。页面分别展示原图、中文标注结果、缺陷目标明细、统计和 YOLO 结论；用户可按需触发大模型复核，查看单独的复核进度与文字结论。历史记录支持缩略图、详情弹窗、删除和 Word 报告导出。
6. **视频检测与视频任务**：上传视频后显示缩略图，以异步任务方式按配置采样检测，持续推送进度并生成可播放结果视频、关键帧和目标明细；支持任务取消、失败恢复、历史查询、详情查看和删除。鼠标悬停关键帧可主动发起大模型复核，复核结果与 YOLO 结果分开展示。
7. **实时检测**：枚举本机 OpenCV 摄像头，允许选择检测模型并配置识别间隔、置信度和 IoU；结合 YOLO 与 ByteTrack 推送实时画面和目标事件，按会话进行重复目标抑制。离开页面或停止会话时自动释放摄像头和后台检测任务。
8. **预警中心**：实时检测发现缺陷后在侧边导航显示消息红点。列表支持搜索、严重程度、处置状态和时间筛选，提供全选、批量处置、批量删除、单条删除、详情和处置方式选择；详情内可由用户主动调用大模型复核，并保留 YOLO 与 AI 两套结论及复核状态。
9. **模型评估**：新建任务时选择待评估模型，并上传单张测试图片及对应的同名 YOLO 标签 `.txt`。系统校验图片与标签、执行 GT/预测框匹配，计算 Precision、Recall、mAP50、mAP50-95，生成真实 PR 数据并展示类别指标和评估运行信息。新建任务会清空页面旧结果，完成后自动切换为当前任务数据。
10. **AI 服务管理**：默认 GLM 模型配置从后端 `.env` 读取并在页面中以只读连接配置展示；管理员可在页面新增、删除、启停和测试动态 OpenAI 兼容模型，分别调整文本模型与视觉多模态模型的调用顺序。保存时动态模型、API Key 和路由顺序持久化到 `runtime/config/ai-models.json`，默认 GLM 仅参与顺序排序，不将其密钥写入 JSON；调用失败时按顺序兜底。
11. **个人中心与系统设置**：支持修改姓名、手机号和邮箱并查看账户信息；管理员可配置默认置信度、默认 IoU、视频采样率、实时检测去重时长、日志级别、临时文件保留周期和 AI 服务，查看运行目录、磁盘及服务状态并执行缓存/临时文件清理。短信 API 等部署级配置统一保存在后端 `.env`，不在普通页面中暴露密钥。设置保存成功或失败均在页面顶部显示数秒后自动消失的消息提示。
12. **本地安全与运行保障**：Flask 仅监听回环地址，Electron 使用隔离上下文、沙箱、CSP 和 preload 白名单；后端统一校验 JWT、管理员权限、上传类型、ZIP 路径、对象键和文件归属。启动时检查 runtime 可写性和磁盘空间，日志按用途存放，异常任务保留明确状态和错误信息，缺少或损坏权重时直接报错而不生成模拟结果。
